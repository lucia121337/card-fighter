# 카드파이터 홈 추천 허브 설계

## 1. 배경과 목표

카드파이터에는 전체카드 검색·필터, 소비 기반 혜택 계산, 카드 비교, 캐시백, 할인가맹점, 카드 연구소가 이미 존재한다. 새 홈은 별도의 추천 기능을 하나 더 만드는 화면이 아니라, 사용자가 자신의 목적에 맞는 추천 경로를 빠르게 고르고 기존 기능으로 이동하도록 돕는 추천 허브로 만든다.

핵심 목표는 다음과 같다.

- 처음 방문한 사용자가 5초 안에 서비스의 용도를 이해한다.
- 사용자가 소비패턴 추천, 혜택 탐색, 카드 비교 중 하나를 바로 시작한다.
- 추천 카드에는 순위뿐 아니라 추천 이유와 주요 조건이 함께 보인다.
- 기존 전체카드·캐시백·할인가맹점·혜택계산기·카드 연구소 기능을 변경하지 않고 연결한다.

## 2. 핵심 사용자

- 어떤 카드를 골라야 할지 기준이 없는 사용자
- 생활비, 쇼핑, 교통·주유, 카페·배달, 여행·마일리지 등 특정 혜택을 찾는 사용자
- 후보 카드 사이의 실질적인 혜택 차이를 계산하거나 비교하려는 사용자
- 신규 발급 캐시백과 할인 이벤트를 함께 살펴보려는 사용자

## 3. 제품 원칙

1. 상품보다 사용자의 목적을 먼저 보여준다.
2. 모든 기능을 같은 무게로 나열하지 않고 추천 시작을 가장 강조한다.
3. 추천 결과에는 반드시 이유, 핵심 조건, 다음 행동을 제공한다.
4. 홈에는 전체 카드 목록을 복제하지 않고 대표 카드만 노출한다.
5. 카드 연구소와 게임형 기능은 탐색을 돕는 보조 영역으로 배치한다.
6. 기존 카드파이터의 파란색 브랜드, 흰색 카드, 절제된 그림자와 둥근 모서리를 유지한다.

## 4. 홈 정보 구조

### 4.1 히어로 및 추천 시작

- 헤드라인: `어떤 카드가 좋은지가 아니라, 나에게 어떤 카드가 유리한지 찾아보세요.`
- 보조 문구: 소비와 관심 혜택을 바탕으로 카드 선택을 돕는다는 점을 한 문장으로 설명한다.
- 기본 CTA: `1분 맞춤 추천 시작` — `calculator.html`로 이동
- 보조 CTA: `혜택으로 직접 찾기`, `카드 비교하기`
- 히어로 오른쪽에는 카드 추천 결과를 연상시키는 요약 패널을 배치한다. 과도한 장식용 이미지는 사용하지 않는다.

### 4.2 추천 경로 선택

세 개의 경로 카드를 제공한다.

1. `내 소비로 추천받기` — 혜택계산기로 이동
2. `원하는 혜택으로 찾기` — 전체카드 영역으로 이동하고 혜택 필터 사용을 유도
3. `후보 카드 비교하기` — 비교함과 비교 기능으로 이동

각 경로는 제목, 한 줄 설명, 예상 소요 시간 또는 결과 형태, 명확한 이동 버튼으로 구성한다.

### 4.3 상황별 빠른 추천

다음 여덟 가지 생활 상황을 선택할 수 있는 칩 또는 작은 카드를 제공한다.

- 생활비
- 쇼핑
- 교통
- 주유
- 카페·디저트
- 여행·숙박
- 항공마일리지
- 프리미엄

선택하면 `전체카드` 섹션으로 전환하고 기존 혜택 카테고리 필터 하나를 자동 적용한다. 매핑은 `생활비→공과금/렌탈`, `쇼핑→쇼핑`, `교통→교통`, `주유→주유`, `카페·디저트→카페/디저트`, `여행·숙박→여행/숙박`, `항공마일리지→항공마일리지`, `프리미엄→프리미엄`으로 고정한다.

### 4.4 지금 주목할 카드

- 기존 카드 데이터에서 대표 카드 3개를 노출한다.
- 각 카드에는 카드 이미지, 카드명, 카드사, 대표 혜택, 전월실적, 추천 이유를 표시한다.
- 순위를 단정하는 표현보다 `생활비에 강한 카드`, `쇼핑 혜택이 큰 카드`처럼 적합한 상황을 설명한다.
- `상세 보기`와 `비교함 담기` 행동을 제공한다.
- 데이터 로드 실패 시 빈 카드 골격을 계속 보여주지 않고 전체카드로 이동하는 안내를 표시한다.

### 4.5 이번 달 혜택

- 기존 캐시백 데이터에서 대표 이벤트를 요약한다.
- 최대 혜택 금액, 플랫폼, 주요 조건을 표시한다.
- 홈에서는 2~3개만 보여주고 `캐시백 전체 보기`로 연결한다.
- 추천 카드보다 위에 배치하지 않아 광고 중심 서비스처럼 보이지 않게 한다.

### 4.6 비교와 판단 도구

- 혜택계산기, 카드 비교, 최근 본 카드 또는 비교함 상태를 한 영역에서 제공한다.
- 비교함에 카드가 있으면 `비교 이어하기`를 가장 먼저 보여준다.
- 저장 상태가 없으면 계산기와 비교 기능의 효용을 짧게 설명하는 기본 화면을 보여준다.

### 4.7 카드 연구소

- 카드 MBTI, 카드 월드컵 등 탐색형 기능을 작은 카드로 소개한다.
- 핵심 추천 흐름 이후에 배치하며 과도한 게임형 비주얼로 홈의 신뢰감을 해치지 않는다.

### 4.8 신뢰 정보

- 카드 데이터 출처, 업데이트 기준, 추천 결과가 참고용이라는 점을 명시한다.
- 카드 상세 조건과 상품설명서를 최종 확인하도록 안내한다.

## 5. 화면 우선순위

홈의 세로 순서는 다음과 같다.

1. 히어로와 추천 시작
2. 세 가지 추천 경로
3. 상황별 빠른 추천
4. 지금 주목할 카드
5. 이번 달 캐시백 혜택
6. 비교와 판단 도구
7. 카드 연구소
8. 데이터 신뢰 정보와 푸터

## 6. 기존 기능 연결

- 홈은 현재 `index.html`의 `section-home` 내부에 구현한다.
- GNB와 검색창, 다른 섹션 전환 방식은 유지한다.
- 전체카드 이동은 기존 `showSection('cards')`를 사용한다.
- 캐시백 이동은 기존 `showSection('cashback')`을 사용한다.
- 혜택계산기는 `calculator.html`, 카드 연구소는 `cardlab.html`로 연결한다.
- 카드 비교는 `compare.html`로 연결한다.
- 카드 상세는 기존 `detail.html?idx={카드번호}` 경로를 사용한다.
- 비교함은 기존 `localStorage` 데이터를 재사용하며 새로운 저장 형식을 만들지 않는다.

## 7. 반응형과 접근성

- 데스크톱은 최대 너비가 제한된 12열 기반 구성을 사용한다.
- 태블릿에서는 3열 경로 카드를 2열 또는 1열로 줄인다.
- 모바일에서는 모든 주요 영역을 한 열로 배치하고 CTA를 손가락으로 누르기 충분한 높이로 제공한다.
- 키보드 포커스, 의미 있는 버튼 문구, 이미지 대체 텍스트, 충분한 색상 대비를 보장한다.
- 움직임은 짧은 호버와 진입 전환만 사용하고 핵심 정보 이해를 방해하는 자동 슬라이드는 사용하지 않는다.

## 8. 성공 기준

- 첫 화면에서 서비스 목적과 대표 행동 세 가지가 보인다.
- 추천 시작, 혜택 탐색, 비교 중 하나를 두 번 이하의 클릭으로 시작할 수 있다.
- 기존 전체카드·캐시백·할인가맹점·혜택계산기·카드 연구소가 계속 정상 동작한다.
- 홈의 대표 카드가 실제 데이터에서 로드되고 카드 상세로 이동한다.
- 데스크톱과 모바일에서 가로 스크롤이 발생하지 않는다.
- 데이터 로드 실패 시 복구 가능한 안내가 표시된다.

## 9. 이번 구현 범위

포함:

- 홈 추천 허브의 HTML, CSS, 최소한의 연결용 JavaScript
- 기존 데이터 기반 대표 카드와 캐시백 요약
- 기존 섹션·페이지로 이동하는 CTA
- 반응형 및 기본 접근성

제외:

- 새로운 추천 알고리즘 개발
- 로그인 및 서버 저장형 개인화
- 새로운 카드 데이터 수집
- 결제·제휴 전환 기능
- 기존 전체카드, 상세, 계산기 화면의 재설계
