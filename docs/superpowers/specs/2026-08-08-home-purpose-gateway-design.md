# 홈 목적 게이트웨이 및 시각 위계 개편 설계

## 1. 배경

현재 홈은 오늘의 매치, 혜택별 탐색, 생활 상황별 대표 카드, 캐시백 순위, 비교함, 카드 연구소를 한 화면에서 모두 강조한다. 개별 기능은 유용하지만 추천 맥락이 여러 개로 나뉘어 사용자가 어떤 추천을 우선 믿고 시작해야 하는지 알기 어렵다. 또한 비슷한 크기의 둥근 카드 박스가 반복되어 각 영역을 강조할수록 오히려 전체 화면의 중심이 약해진다.

홈의 역할을 새로운 추천 결과를 하나 더 보여주는 곳에서, 사용자가 카드를 찾는 목적을 확인하고 기존 기능 중 가장 알맞은 경로로 안내하는 단일 게이트웨이로 바꾼다.

## 2. 목표

- 첫 방문자가 5초 안에 서비스의 용도와 첫 행동을 이해한다.
- 홈에는 실제 추천 결과 대신 세 개의 공식 탐색 경로만 강하게 제시한다.
- 이미 진행한 탐색이 있으면 사용자가 멈춘 지점과 다음 행동을 짧게 보여준다.
- 카드 연구소는 핵심 탐색을 방해하지 않으면서 취향 기반 기능의 재미를 전달한다.
- 전체카드, 상세, 비교, 계산기와 동일한 색상·타이포그래피 체계를 사용한다.
- 데스크톱과 모바일 모두 가로 스크롤 없이 동일한 정보 위계를 유지한다.

## 3. 비목표

- 새로운 추천 알고리즘을 만들지 않는다.
- 카드 데이터, 혜택 데이터, 캐시백 데이터의 수집 방식을 변경하지 않는다.
- 계산기, 전체카드, 카드 상세, 비교, 카드 연구소의 내부 화면을 재설계하지 않는다.
- 로그인이나 서버 저장형 개인화를 추가하지 않는다.
- 홈에 별도의 인기 카드, 오늘의 카드 또는 자동 추천 순위를 추가하지 않는다.

## 4. 핵심 제품 결정

### 4.1 홈은 추천 결과가 아니라 목적 선택을 제공한다

홈의 첫 행동은 다음 세 가지로 고정한다.

1. **매달 가장 이득인 카드**
   - 설명: 내 소비금액으로 월 혜택과 연회비를 계산한다.
   - 이동: `calculator.html`
2. **지금 받을 수 있는 발급 혜택**
   - 설명: 카드사별 캐시백과 주요 조건을 확인한다.
   - 이동: 기존 캐시백 경로 `/event`
3. **원하는 혜택이 있는 카드**
   - 설명: 카페, 주유, 교통 등 혜택 카테고리로 직접 탐색한다.
   - 이동: `/card#benefit-filters`. 전체카드의 혜택 필터에 `benefit-filters` 식별자를 부여하고 진입 시 해당 영역으로 스크롤한다.

상단 검색창은 카드 이름이나 구체적인 혜택을 이미 알고 있는 사용자를 위한 별도 직행 경로로 유지한다.

### 4.2 홈에서 제거하는 기존 영역

- 오늘의 매치
- 혜택으로 바로 찾기 칩 목록
- 생활 상황별 대표 카드와 내 소비 기준 Top 3
- 이번 달 캐시백 순위 목록
- 비교함이 비어 있을 때 표시하는 큰 안내 패널

해당 기능과 데이터는 삭제하지 않는다. 계산기, 전체카드, 캐시백 페이지 등 목적에 맞는 기존 화면에서 계속 제공한다.

## 5. 화면 구성

### 5.1 상단 내비게이션

현재 로고, 메뉴, 검색창과 라우팅 동작을 유지한다. 홈 활성 상태만 기존 방식대로 표시한다.

### 5.2 첫 장면: Editorial Arena

홈에서 시각적 강도가 가장 높은 유일한 영역이다.

- 왼쪽에는 큰 제목 `카드를 고르기 전에, 이유부터 고르세요.`를 배치한다.
- 보조 문구는 목적 하나를 선택하면 알맞은 기능으로 연결된다는 점을 설명한다.
- 오른쪽에는 `cards_list.json`에서 유효한 `card_img`가 있는 앞쪽 세 장을 순서대로 골라 겹쳐 배치한다. 이 이미지는 추천 결과가 아닌 데이터 규모를 보여주는 장식이며 클릭할 수 없다.
- 배경의 큰 `1276` 숫자는 장식이며, 실제 노출 문구의 카드 수는 `cards_list.json` 배열 길이로 갱신한다.
- 이미지가 실패하면 해당 이미지만 숨기고 레이아웃은 유지한다.
- 장식용 숫자와 카드 이미지는 스크린리더에서 제외한다.

### 5.3 목적 메뉴: 01·02·03

히어로 바로 아래에 화면 폭을 가로지르는 세 개의 경로를 둔다.

- 01은 브랜드 블루 배경의 주 경로로 표시한다.
- 02와 03은 흰색 배경과 얇은 구분선으로 표시한다.
- 각 항목은 번호, 아이콘, 제목, 한 줄 설명, 이동 표시로 구성한다.
- 전체 영역을 클릭 가능한 링크로 만든다.
- hover, focus-visible, active 상태를 제공하되 과한 애니메이션은 사용하지 않는다.

### 5.4 지난 탐색 이어하기

시각 강도는 첫 장면의 절반 수준으로 제한한다. 큰 배너가 아니라 흰색 바탕의 얇은 진행 상황 영역으로 만든다.

- 소비 프로필과 비교함이 모두 없으면 영역 전체를 렌더링하지 않는다.
- 소비 프로필이 있으면 `소비 기준 저장`과 `추천 확인` 상태를 표시하고 `다시 계산`을 제공한다.
- 비교함에 카드가 두 장 이상 있으면 `카드 비교 중` 상태와 `비교 이어보기`를 제공한다.
- 한 종류의 상태만 있으면 존재하는 상태와 관련 행동만 표시한다.
- 사용자가 다음에 해야 할 행동을 하나의 주 버튼으로 강조한다.
- 저장 시각처럼 실제로 보유하지 않은 정보는 만들지 않는다.

### 5.5 카드 연구소

카드 연구소는 핵심 경로 이후의 보조 탐색이다. 두 기능을 작은 체험 입구로 나란히 배치한다.

- 소비 MBTI: 연한 보라 계열의 아이콘 영역, 질문형 제목 `나는 어떤 소비형일까?`
- 카드 월드컵: 연한 블루 계열의 아이콘 영역, 질문형 제목 `마지막까지 살아남을 카드는?`
- 두 항목 모두 흰색 바탕을 유지하고 강한 전체 배경색, 큰 숫자, 실제 카드 이미지는 사용하지 않는다.
- 데스크톱에서는 2열, 모바일에서는 1열로 쌓는다.
- `카드 연구소 전체` 링크를 섹션 제목 오른쪽에 제공한다.

### 5.6 신뢰 정보

페이지 하단에 가장 낮은 시각 강도로 다음 내용을 한 줄 또는 짧은 문장으로 제공한다.

- 현재 비교 카드 수
- 월 순이득은 혜택에서 월 환산 연회비를 뺀 값이라는 설명
- 추천 조건 공개 및 원문 검수 안내
- 최종 신청 전 카드사 상품설명서와 약관을 확인하라는 안내

## 6. 시각 위계

모든 영역이 동시에 경쟁하지 않도록 강도를 다음처럼 제한한다.

| 영역 | 상대 강도 | 표현 원칙 |
|---|---:|---|
| 첫 장면 | 100 | 큰 타이포, 실제 카드 이미지, 넓은 여백 |
| 목적 메뉴 | 80 | 화면 폭 전체, 큰 번호, 주 경로만 블루 배경 |
| 지난 탐색 | 50 | 흰색 진행 바, 작은 상태 원과 한 개의 주 버튼 |
| 카드 연구소 | 40 | 흰색 소형 입구 두 개, 연한 보조색 |
| 신뢰 정보 | 20 | 얇은 구분선과 작은 회색 텍스트 |

첫 장면 이외에는 큰 배경 숫자, 겹친 카드 이미지, 전체 면적의 강한 블루 배경을 사용하지 않는다.

## 7. 디자인 시스템

기존 서비스의 공통 시각 언어를 따른다.

- 기본 배경: `#f5f7fa`
- 패널: `#ffffff`
- 보조 패널: `#e8f0fd`
- 구분선: `#e2e8f0`
- 본문: `#1e293b`
- 보조 텍스트: `#64748b`
- 브랜드 블루: `#145ce6`
- 진한 브랜드 블루: `#0e47c0`
- 노랑 `#f2c94c`은 배지나 현재 단계처럼 작은 강조에만 사용한다.
- 글꼴은 기존 `GmarketSans`, `Noto Sans KR`, 시스템 폰트 순서를 유지한다.
- 기존 상세·비교 화면과 같은 모서리, 그림자, 버튼 높이를 사용한다.

## 8. 상태와 데이터 흐름

홈 전용 상태는 새로 저장하지 않는다.

- 카드 수와 장식 카드 후보: `cards_list.json`
- 소비 기준: 기존 `CardProfile` 저장값
- 비교 상태: 기존 `localStorage` 비교함 데이터
- 목적 메뉴 이동: 기존 페이지와 라우팅 함수

홈 렌더러는 데이터 로드 성공 여부와 저장 상태를 받아 각 독립 영역의 표시 여부와 문구만 결정한다. 추천 순위 계산은 홈에서 실행하지 않는다.

## 9. 구성 단위

홈 코드는 다음 책임으로 분리한다.

1. **목적 경로 모델**: 세 경로의 제목, 설명, 아이콘, URL을 제공한다.
2. **홈 상태 어댑터**: 카드 수, 소비 프로필, 비교함 상태를 기존 저장소에서 읽는다.
3. **홈 뷰 렌더러**: 히어로, 목적 메뉴, 이어하기, 카드 연구소, 신뢰 정보를 렌더링한다.
4. **상호작용 바인더**: 링크, 키보드 포커스, 기존 라우팅 연결만 담당한다.

추천 계산과 캐시백 정렬은 홈 렌더러의 책임에서 제외한다.

## 10. 오류 및 빈 상태

- `cards_list.json`을 읽지 못하면 카드 수는 `수많은 카드`로 표시한다.
- 실제 카드 이미지 중 일부가 실패하면 실패한 이미지만 숨긴다.
- 소비 프로필과 비교함이 없으면 이어하기 영역을 숨기고 빈 상태 패널을 만들지 않는다.
- 비교함이 한 장뿐이면 비교 시작을 재촉하지 않고 해당 카드가 저장되었다는 정보와 카드 찾기 링크만 제공한다.
- 목적 경로는 데이터 로드와 무관하게 항상 동작한다.

## 11. 반응형 및 접근성

- 860px 이하에서 히어로 문구와 카드 이미지를 세로로 배치한다.
- 720px 이하에서 목적 메뉴를 한 줄씩 쌓는다.
- 모바일에서는 장식 카드 수를 두 장으로 줄이고 제목 크기를 낮춘다.
- 이어하기 상태는 모바일에서 가로 타임라인 대신 세로 또는 짧은 문장형 요약으로 표시한다.
- 모든 링크와 버튼은 최소 44px 높이, 명확한 `focus-visible`, 충분한 색상 대비를 가진다.
- 아이콘만으로 의미를 전달하지 않고 항상 텍스트를 함께 제공한다.
- 사용자가 `prefers-reduced-motion`을 설정하면 장식 이동과 hover 변형을 제거한다.

## 12. 검증 기준

- 홈 첫 화면에 서비스 설명과 세 가지 목적 경로가 보인다.
- 홈에는 추천 카드 순위, 오늘의 매치, 캐시백 순위가 표시되지 않는다.
- 각 목적 경로가 계산기, 캐시백, 전체카드의 올바른 위치로 이동한다.
- 카드 수가 `cards_list.json` 길이와 일치한다.
- 저장 상태가 없을 때 이어하기 영역이 표시되지 않는다.
- 소비 프로필 또는 비교함이 있을 때 관련 상태와 다음 행동만 표시된다.
- 카드 연구소 두 입구가 기존 기능으로 이동한다.
- 360px 모바일에서 가로 스크롤이 생기지 않는다.
- 기존 전체카드, 상세, 비교, 계산기, 캐시백 라우팅이 그대로 동작한다.
- 홈 렌더링 단위 테스트와 기존 프로젝트 테스트가 모두 통과한다.

## 13. 구현 영향 범위

예상 수정 대상은 홈 전용 마크업과 스타일, 홈 렌더링 스크립트, 홈 테스트다. 공통 데이터 JSON과 API는 수정하지 않는다. 제거되는 홈 영역만 사용하던 스크립트와 스타일은 다른 소비자가 없는지 확인한 뒤 런타임 연결을 제거하거나 정리한다.
