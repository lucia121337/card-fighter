# 홈 히어로 카드 랜덤 등장 모션 디자인

## 목표

메인 홈을 새로 열 때 히어로의 카드 이미지가 매번 다른 조합으로 등장하도록 한다. 세 장은 아래에서 순서대로 올라온 뒤 현재 배치와 회전 각도에 부드럽게 감속하며 멈춘다. 모션은 홈의 첫인상을 강화하되 목적 메뉴보다 더 강한 주목을 끌지 않는다.

## 범위

- 현재 `cards_list.json`에서 불러온 활성 카드 중 `card_img`가 있는 카드를 사용한다.
- 한 번의 선택에서는 서로 다른 카드 세 장을 고른다.
- 페이지를 새로 열 때마다 새 조합을 고른다.
- 같은 문서 안에서 홈과 다른 메뉴를 오갈 때는 처음 고른 조합을 유지한다.
- 데스크톱은 세 장, 모바일은 기존 규칙대로 두 장만 보여준다.

카드 데이터, API, 카드 상세 페이지, 목적 메뉴 구조는 변경하지 않는다.

## 선택 방식

`HomeGateway`가 첫 번째 비어 있지 않은 카드 배열을 받으면 이미지가 있는 카드만 후보로 만든다. 후보를 무작위로 섞은 뒤 앞에서 세 장을 선택하며, 선택 결과를 현재 페이지 생명주기 동안 캐시한다. 이후 `updateCards`가 다시 호출되더라도 같은 결과를 사용한다. 새로고침하면 모듈 상태가 초기화되어 새 조합이 선택된다.

테스트에서 결과를 재현할 수 있도록 선택 함수는 기본값으로 `Math.random`을 사용하되 난수 함수를 주입할 수 있게 한다.

후보가 세 장보다 적으면 가능한 카드만 표시한다. 이미지 로드가 실패하면 기존 `onerror` 동작대로 해당 이미지만 숨긴다.

## 모션

각 카드는 최종 위치보다 아래쪽 약 120px, 불투명도 0, 크기 96%에서 시작한다. 약 0.7초 동안 `cubic-bezier(0.16, 1, 0.3, 1)` 감속 곡선을 사용해 현재 위치·크기·회전 각도에 도착한다.

- 첫 번째 카드: 지연 없음
- 두 번째 카드: 0.12초 지연
- 세 번째 카드: 0.24초 지연

카드는 튀거나 반복해서 흔들리지 않는다. 애니메이션은 처음 카드 조합이 렌더링될 때 한 번만 실행하고, 같은 페이지에서 다시 실행하지 않는다.

현재 카드별 회전 각도와 위치는 CSS 사용자 정의 속성으로 보존한다. 모션의 시작·종료 transform이 기존 레이아웃 transform을 덮어쓰지 않도록 카드별 최종 회전을 변수로 합성한다.

## 반응형 및 접근성

- 720px 이하에서는 세 번째 카드를 계속 숨긴다.
- 모바일에서도 두 카드의 시간차와 감속 방식은 유지하되 현재 축소 배치를 바꾸지 않는다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 지연을 제거하고 최종 위치에 즉시 표시한다.
- 카드 이미지는 장식용이므로 기존 `aria-hidden="true"`와 빈 대체 텍스트를 유지한다.

## 목적 메뉴 라인 아이콘

목적 메뉴 01·02·03에 사용 중인 의미가 불분명한 특수문자 `□`, `◒`, `◈`를 맞춤 라인 아이콘으로 교체한다. 별도 PNG나 외부 아이콘 라이브러리를 추가하지 않고, 현재 색상을 상속하는 인라인 SVG를 사용한다. 확대 화면에서도 선이 선명하고 네트워크 오류에 영향을 받지 않도록 한다.

- 01 매달 가장 이득인 카드: 카드 결제면과 상승 화살표를 결합한 계산 아이콘
- 02 지금 받을 수 있는 발급 혜택: 리본이 있는 선물 상자 아이콘
- 03 원하는 혜택이 있는 카드: 혜택 격자와 돋보기를 결합한 탐색 아이콘

세 아이콘은 28px 정사각형, 약 1.8px 선 굵기, 둥근 선 끝을 공통 규칙으로 사용한다. 선택된 첫 번째 메뉴에서는 흰색, 나머지 메뉴에서는 기존 네이비 색상을 상속한다. 아이콘은 텍스트 제목을 보조하는 장식 요소이므로 `aria-hidden="true"`를 적용하고 별도의 반복 설명은 넣지 않는다. 배지·배경·추가 애니메이션은 사용하지 않아 목적 메뉴의 현재 위계를 유지한다.

## 데이터 흐름

1. 기존 카드 목록 요청이 완료된다.
2. `HomeGateway.updateCards(DATA)`가 호출된다.
3. 아직 선택된 카드가 없으면 후보를 필터링하고 세 장을 무작위 선택한다.
4. 선택 결과를 캐시하고 카드 마크업을 렌더링한다.
5. CSS가 각 카드의 지연값과 회전값을 이용해 한 번만 등장 모션을 실행한다.

목적 메뉴 아이콘은 정적 마크업이며 카드 선택·렌더링 흐름과 독립적으로 동작한다.

## 검증

- 이미지가 있는 카드만 선택되는지 확인한다.
- 한 번의 선택에서 카드가 중복되지 않는지 확인한다.
- 주입한 난수로 결과를 재현할 수 있는지 확인한다.
- 같은 페이지의 반복 업데이트에서는 선택 결과가 유지되는지 확인한다.
- 새 페이지 로드에 해당하는 새 모듈 상태에서는 다시 선택 가능한지 확인한다.
- CSS에 0.12초 간격, 약 0.7초 감속, 120px 시작 위치가 포함되는지 확인한다.
- reduced-motion과 모바일의 세 번째 카드 숨김 규칙을 확인한다.
- 목적 메뉴에 특수문자가 남지 않고 세 가지 인라인 SVG가 올바른 목적에 배치되는지 확인한다.
- 아이콘이 `currentColor`를 사용하고 장식용 접근성 속성을 갖는지 확인한다.
- 데스크톱과 360·375·390·412px에서 가로 넘침과 최종 카드 위치 변화를 확인한다.

## 변경 예정 파일

- `home-gateway.js`: 무작위 선택, 페이지 생명주기 캐시, 테스트 가능한 난수 주입
- `home-gateway.css`: 카드별 최종 회전 변수와 순차 등장 애니메이션
- `index.html`: 목적 메뉴의 특수문자를 의미가 분명한 인라인 SVG 세 개로 교체
- `src/picking/test_home_gateway.js`: 선택·캐시·모션 계약 회귀 테스트

## 완료 기준

- 새로고침할 때 카드 조합이 바뀔 수 있다.
- 한 화면에 동일 카드가 중복되지 않는다.
- 카드는 아래에서 순차적으로 올라와 튕김 없이 제자리에 멈춘다.
- 홈 내부 이동만으로는 카드 조합이나 모션이 다시 시작되지 않는다.
- 모바일·키보드·움직임 줄이기 설정에서 기존 사용성이 유지된다.
- 01·02·03 메뉴가 계산·발급 혜택·카테고리 탐색 의미를 시각적으로 전달한다.
- 기존 홈 및 계산기 관련 테스트가 통과한다.
