# 카드 토너먼트 기능 작업계획서

> 상태: 설계/논의용 초안  
> 목표: 사용자가 관심 카테고리와 월 소비금액을 입력하면, 추천 카드 32개로 토너먼트를 진행하고 최종 우승 카드의 예상 혜택을 보여준다.

## 1. 기능 한 줄 설명

사용자가 관심 있는 혜택 카테고리를 고르면, 해당 소비패턴에 잘 맞는 카드 32장을 뽑아 카드 월드컵처럼 비교하게 하고, 마지막에 가장 마음에 드는 카드의 예상 월 혜택과 상세 설명을 보여주는 기능이다.

## 2. 왜 필요한가

- 카드가 너무 많아서 사용자가 직접 고르기 어렵다.
- 단순 목록 추천보다 토너먼트 방식이 재미있고 선택 과정이 쉽다.
- 현재 카드 데이터의 `benefit_categories`, `top_benefit_summary`, `pre_month_money`를 활용할 수 있다.
- 추후 개발 중인 카드 혜택 계산기와 연결하면 개인 맞춤 추천 기능으로 확장할 수 있다.

## 3. 사용자 흐름

1. 사용자가 카드 토너먼트 페이지에 들어온다.
2. 관심 있는 카테고리를 선택한다.
   - 예: 쇼핑, 카페/디저트, 교통, 푸드, 통신
3. 월 소비금액을 입력한다.
   - 예: 쇼핑 300,000원, 카페 80,000원, 교통 70,000원
4. 시스템이 카드 후보를 계산한다.
5. 점수가 높은 카드 상위 32개를 뽑는다.
6. 32강 토너먼트를 시작한다.
7. 사용자는 매 라운드에서 더 마음에 드는 카드를 선택한다.
8. 최종 우승 카드가 나오면 결과 화면을 보여준다.
9. 결과 화면에서 예상 혜택, 추천 이유, 상세보기 링크를 제공한다.

## 4. 사용할 데이터

### 기본 카드 목록

- 파일: `cards_list.json`
- 사용 필드:
  - `idx`: 카드 고유 번호
  - `card_name`: 카드명
  - `company`: 카드사
  - `card_img`: 카드 이미지
  - `annual_fee`: 연회비
  - `pre_month_money`: 전월실적
  - `benefit_categories`: 혜택 카테고리
  - `top_benefit_summary`: 주요 혜택 요약

### 카드 상세 정보

- 폴더: `card_detail/`
- 사용 시점:
  - 최종 우승 카드 결과 화면
  - 혜택 상세 설명
  - 예상 혜택 계산 보조

## 5. 후보 32개를 뽑는 기준

1차 버전에서는 너무 복잡하게 만들지 않고 아래 기준으로 뽑는다.

1. 사용자가 고른 카테고리가 `benefit_categories`에 포함된 카드만 남긴다.
2. 사용자의 월 소비금액이 카드 전월실적보다 크거나 같으면 높은 점수를 준다.
3. `top_benefit_summary`에 선택 카테고리와 관련된 할인율, 적립률, 최대금액이 있으면 점수를 준다.
4. 연회비가 너무 높으면 약간 감점한다.
5. 최종 점수 기준 상위 32개를 뽑는다.

후보가 32개보다 적으면 16강 또는 8강으로 자동 축소한다.

## 6. 예상 혜택 계산 방식

정확한 계산기는 추후 혜택 계산기 담당자의 기능과 연결한다.

1차 버전에서는 간단 계산으로 시작한다.

```text
예상 월 혜택 =
  카테고리별 월 소비금액 × 예상 할인율
  단, 월 할인한도가 문구에서 확인되면 그 한도를 넘지 않게 계산
```

예시:

```text
카페 소비금액: 80,000원
카드 혜택: 카페 20% 할인
예상 혜택: 16,000원
월 할인한도: 10,000원
최종 예상 혜택: 10,000원
```

계산이 어려운 카드는 "예상 혜택 확인 필요"로 표시한다.

## 7. 토너먼트 진행 방식

### 라운드

- 32강
- 16강
- 8강
- 4강
- 결승
- 최종 결과

### 매치 화면

각 카드에는 아래 정보를 보여준다.

- 카드 이미지
- 카드명
- 카드사
- 연회비
- 전월실적
- 주요 혜택 2~3줄
- 예상 월 혜택

사용자는 두 카드 중 하나를 선택한다.

## 8. 결과 화면

최종 우승 카드에는 아래 내용을 보여준다.

- 우승 카드 이미지
- 카드명, 카드사
- 예상 월 혜택
- 선택한 카테고리와 맞는 이유
- 주요 혜택 설명
- 전월실적/연회비 정보
- `detail?idx=카드번호` 상세보기 링크

## 9. 개발 파일 계획

충돌을 줄이기 위해 1차 구현은 새 페이지로 만든다.

### 새로 만들 파일

- `tournament.html`
  - 카드 토너먼트 화면
  - 카테고리 선택
  - 소비금액 입력
  - 토너먼트 진행
  - 결과 화면

### 나중에 수정할 수 있는 파일

- `index.html`
  - 메인 메뉴에 "카드 토너먼트" 진입 버튼 추가
  - 공통 파일이므로 수정 전 팀에 먼저 공유 필요

- `vercel.json`
  - `/tournament` 주소로 접속하게 하고 싶을 때 수정
  - 공통 파일이므로 수정 전 팀에 먼저 공유 필요

## 10. 개발 단계

### 1단계: 설계 확정

- 카테고리 목록 확정
- 월 소비금액 입력 방식 확정
- 32강 후보 선정 기준 확정
- 결과 화면에 보여줄 정보 확정

### 2단계: 토너먼트 페이지 기본 구현

- `tournament.html` 생성
- `cards_list.json` 로드
- 카테고리 선택 UI 구현
- 월 소비금액 입력 UI 구현

### 3단계: 후보 카드 추천 로직 구현

- 선택 카테고리 기준 필터
- 전월실적 기준 점수 계산
- 혜택 요약 기준 점수 계산
- 상위 32개 카드 추출

### 4단계: 토너먼트 UI 구현

- 32강 매치 생성
- 카드 2장 비교 화면
- 선택한 카드 다음 라운드 진출
- 라운드 진행 상태 표시

### 5단계: 최종 결과 화면 구현

- 우승 카드 표시
- 예상 월 혜택 표시
- 추천 이유 표시
- 상세보기 링크 연결

### 6단계: 검증

- 로컬 서버 실행: `python serve.py`
- 카드 데이터 로딩 확인
- 32강 시작 확인
- 후보가 32개 미만일 때 처리 확인
- 모바일 화면에서 카드 비교 UI 확인
- 콘솔 에러 확인

## 11. 역할 분리

### 토너먼트 담당

- `tournament.html` 화면 구현
- 토너먼트 라운드 진행 로직
- 최종 결과 화면 구현

### 혜택 계산기 담당

- 월 소비금액 기준 예상 혜택 계산 로직
- 할인율, 적립률, 월 한도 계산 규칙 정리
- 계산 결과를 토너먼트에서 사용할 수 있는 함수 형태로 제공

### 데이터 담당

- `cards_list.json`의 카테고리 품질 확인
- 잘못된 카테고리나 누락된 혜택 정리
- 상세 데이터 `card_detail/` 확인

## 12. 주의할 점

- `main` 브랜치에서 직접 작업하지 않는다.
- 항상 `feature/*` 브랜치에서 작업한다.
- 구현 전에 `git pull origin main`으로 최신 상태를 받는다.
- `index.html`, `vercel.json`, `cards*.json`, `api/*`를 수정해야 하면 팀에 먼저 알린다.
- `.env`, API 키, Redis 토큰, `node_modules`는 절대 커밋하지 않는다.
- 작업 후 로컬 미리보기로 직접 확인한다.

## 13. 1차 버전 완료 기준

- 사용자가 카테고리와 월 소비금액을 입력할 수 있다.
- 입력값을 기준으로 카드 후보를 자동으로 뽑는다.
- 32강 또는 축소 토너먼트를 진행할 수 있다.
- 최종 우승 카드가 표시된다.
- 우승 카드의 예상 혜택과 추천 이유가 표시된다.
- 상세보기 페이지로 이동할 수 있다.

## 14. 추후 확장 아이디어

- 사용자가 32강, 16강, 8강 중 직접 선택
- 토너먼트 결과 저장
- 친구에게 결과 공유
- 비교함 담기 연동
- 계산기 담당 기능과 완전 연동
