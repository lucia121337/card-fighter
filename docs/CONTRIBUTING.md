# 프로젝트 기여 가이드라인 (CONTRIBUTING.md)

이 저장소에서 작업을 시작하기 전에 반드시 본 가이드라인(팀 협업 규칙)을 먼저 읽고 준수해 주시기 바랍니다.

## 📌 핵심 규칙

### 1. 브랜치 관리 및 작업 방식
- `main` 및 `develop` 브랜치에 직접 작업을 하거나, 커밋 또는 push하는 행위는 **절대 금지**됩니다.
- 모든 작업은 항상 `feature/*` 브랜치(예: `feature/기능명`)를 생성하여 진행해야 합니다.
- 작업을 시작하기 전에는 항상 다음 명령어를 통해 `develop` 브랜치의 최신 변경 사항을 로컬에 반영해야 합니다:
  ```bash
  git pull origin develop
  ```

### 2. 커밋 메시지 규칙
- 커밋 메시지는 정해진 접두사(`feat`, `fix`, `docs`, `refactor`, `style` 등)를 사용하여 규칙적으로 작성해야 합니다.
- **"최종", "수정", "완료"** 등 모호하거나 의미 없는 메시지는 사용을 금지합니다.
- **예시:**
  - `feat: 카드 비교 기능 추가`
  - `fix: 상세 페이지 모달 레이아웃 깨짐 현상 수정`
  - `docs: CONTRIBUTING.md 가이드라인 추가`

### 3. 보안 및 대용량 데이터 관리
- `.env` 파일, API 키, 그리고 대용량 원본 데이터 파일은 **절대로 커밋 및 push하지 마십시오.**
- 민감한 설정 정보 및 대용량 원본 데이터는 `.gitignore`에 등록하여 관리해야 합니다.

### 4. 공통 파일 수정 및 소통
- 라우터(Router), 공통 설정, 카테고리 등 여러 명의 작업자에게 영향을 줄 수 있는 **공통 파일**을 수정할 때는 작업 착수 전에 반드시 팀원들에게 미리 공유하고 합의를 거쳐야 합니다.

### 5. 코드 병합 (PR)
- 로컬에서 작업 완료 후 반드시 직접 실행하여 정상 동작 여부를 확인해야 합니다.
- 모든 변경 사항은 직접 병합할 수 없으며, **풀 리퀘스트(Pull Request, PR)**를 통해서만 병합을 진행할 수 있습니다.
