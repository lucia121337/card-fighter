## 0. 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| 계산 로직 | **`benefit-calc.js`(BenefitCalc) 공용 모듈만 사용.** 토너먼트 안에 계산식 복붙 금지 |
| 전월실적 | 카테고리 소비와 **별도 입력**. 비우면 소비 합계로 간주. 한도 tier 선택·실적조건 판정 기준 |
| 마일·포인트 카드 | **트랙 분리.** 시작 화면에서 💰현금할인형 / ✈️마일·포인트형 중 선택. 원 환산 금지 |
| 단위 표시 | 원은 원, 마일은 마일, 포인트는 포인트 (Option D 원칙 그대로) |
| 파일 | `tournament.html` 신규 1파일. `vercel.json` 수정 안 함(직접 .html 링크) |
| 진입점 | `index.html` GNB에 "🏆 카드 토너먼트" 링크 — 공통파일이므로 PR에 명시 |

## 1. 사용자 흐름 (1차)

```
[1] 트랙 선택 (💰 현금할인 / ✈️ 마일·포인트)
[2] 관심 카테고리 선택 (다중, 최소 1개)
[3] 카테고리별 월 소비액 + 평소 월 카드 사용액(전월실적) 입력
[4] 32강 자동 선발 → 토너먼트 (후보 부족 시 16/8강 자동 축소)
[5] 매 라운드 2장 비교 → 선택
[6] 우승 카드 결과: 예상 혜택·추천 이유·상세보기 링크
```

## 2. 32강 선발 로직

```js
후보 = 전체 카드 중
  ① BenefitCalc.track(b) === 선택트랙 ('money' | 'unit')
  ② 선택 카테고리 중 1개 이상이 benefit_categories에 포함
r = BenefitCalc.calc(b, spending, {prevMonth})
정렬 = 실적충족(r.meetsPreMonth) 우선 → BenefitCalc.score(r) 내림차순
     → 동점이면 매칭 카테고리 수 → 낮은 연회비
상위 32장 (31~17장이면 16강, 15~9장이면 8강, 8장 미만이면 안내 후 조건 완화 제안)
```

- `score()`: money 트랙 = 월 순이득(net), unit 트랙 = 마일/포인트 적립량 — 단위를 섞지 않는다.
- 대진: 시드 페어링(1위 vs 32위, 2위 vs 31위 …) — 강한 카드가 초반에 서로 떨어지게.

## 3. 매치 카드에 보여줄 것 (계획서 §7)

카드 이미지 / 카드명 / 카드사 / 연회비 / 전월실적 조건(미달 시 경고 칩) /
매칭 카테고리 칩(율) / **예상 월 혜택**(money: N원·한도 적용 표시, unit: N마일 or N포인트)

## 4. 결과 화면 (계획서 §8)

우승 카드 + 예상 월 혜택(단위별) + 추천 이유(매칭 카테고리·실적 충족) +
연회비/실적 정보 + `detail?idx=` 상세보기 + 준우승·4강 카드 간단 표시

## 6. 검증 기준 (완료 조건)

- money 트랙: 32강 시작 → 결승 → 우승 카드 예상 혜택이 detail 계산기와 **동일 숫자**
- unit 트랙: 마일/포인트 카드만 나오고 금액이 원으로 표시되지 않는다
- 전월실적을 낮추면 tier 한도 카드의 예상 혜택이 줄어든다 (1003으로 확인)
- 후보가 32장 미만인 조합에서 자동 축소가 동작한다
- 콘솔 에러 0

## 7. 역할

- 이 문서의 구현: 혜택 계산기 담당(본인). 토너먼트 UI 고도화·디자인은 토너먼트 담당과 협의.
- 계산 규칙 변경은 반드시 `benefit-calc.js`에서만 — 세 페이지 숫자가 항상 일치해야 함.
