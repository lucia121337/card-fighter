## 1. 캐시백 데이터 — 카드사(company) 복원

### 문제
카드고릴라 이벤트 API(`https://api.card-gorilla.com:8080/v1/events`)의 `corp_name`은
실제 카드사가 아니라 **기획전 그룹명**(`트래블`·`JCB`·`ALPHABET`·`추가캐시백`·`지난 이벤트` 등)인
경우가 많다. 그래서 제목만 보고 카드사를 뽑던 기존 `extractCompany()`는 **186건 중 93건(50%)이
`기타`로 샜다.** → 화면에 있을 수 없는 "기타카드" 그룹이 생김.

### 복원 규칙 (우선순위) — `event_study/crawl_events.py`의 `resolve_company()`
1. **`corp_idx`(안정적 카드사 ID)** → 실제 카드사면 그대로 사용
   - `1 삼성 · 2 신한 · 3 KB국민 · 4 롯데 · 5 우리 · 7 현대 · 8 하나 · 9 NH농협 · 10 IBK기업 · 32 BC바로`
2. **`card_idxs`** → 카드 상세 API(`/v1/cards/{idx}`)의 `corp.name`으로 발급사 조회
3. **제목·부제**의 카드사 별칭/브랜드명 매칭 (예: `알파벳`·`대한항공카드`→현대, `LOCA`→롯데, `올바른`·`zgm`→NH)
4. `corp_name`이 `JCB`처럼 실제 브랜드면 그대로 유지 (기타 아님)
5. **상세 본문의 카드사 언급 빈도 최다값** (마지막 폴백)
- 노이즈(`corp_idx=67` "이벤트 등록용/팝업구조 TEST")는 제외.

### 결과
- 186건 → **185건**(노이즈 1건 제외), **미복원(=기타) 0건.**
- 분포: 현대47 · NH농협32 · 삼성25 · 신한18 · BC바로12 · KB국민12 · IBK기업11 · 롯데9 · JCB8 · 우리6 · 하나4 · 현대백화점1
- 각 이벤트에 **`company` 필드**를 새로 저장. `index.html`은 `e.company`를 우선 사용
  (`loadGorilla()`, 폴백으로만 `extractCompany`).

### 데이터 갱신 방법
```
card-reco/.venv 파이썬으로:
python event_study/crawl_events.py
```
→ `event_study/cashback_events.json`(분석용, detail_html 포함) +
  루트 `cashback_events.json`(프로덕션, index.html이 fetch) + `.csv` 동시 생성.

## 2. 전체카드 탭 — 필터 고도화 (`index.html`)

기존 `<select>` 3개(카드사·연회비·전월실적)를 팝오버형 컴포넌트로 교체.

### ① 카드사 — 검색 + 체크박스 다중선택
- 버튼 클릭 → 팝오버에 **검색창 + 체크박스 목록**(카드사별 카드 수 표시, 많은순 정렬).
- 여러 카드사 동시 선택(OR). 전체선택/전체해제 버튼. 버튼 라벨은 `카드사 N곳`.
- 목록은 `cards_list.json`에서 동적 생성 → 데이터 바뀌어도 자동 반영.

### ② 연회비 — 구간 듀얼 슬라이더
- 정상적인 선형 슬라이더는 무의미(무료~300만원, 대부분 1~2만원에 몰림).
- **비선형 스톱**으로 구성: `무료 · 1만 · 2만 · 3만 · 5만 · 10만 · 무제한`.
- 두 개 thumb으로 상·하한 구간 지정. 대표 연회비 = **최대값**(`feeMax`, 👑프리미엄 판정과 동일 기준).

### ③ 전월실적 — 특징 구간 다중선택 (데이터 분석 기반)
`cards_list.json` 1,563장 분포를 분석해 자연 군집으로 5구간 분할:

| 구간 | 조건 | 카드 수 | 근거 |
|---|---|---|---|
| 무실적 | 0원 | 490 | 실적 조건 없는 카드 |
| 20만원↓ | 1~20만 | 174 | 10만·15만·20만 소액 구간 |
| 30만원대 | 21~30만 | 474 | **최대 군집**(30만이 460장, 국내 표준 실적) |
| 40~50만원 | 31~50만 | 412 | 40만(168)+50만(244) |
| 50만원↑ | 50만 초과 | 14 | 70~150만 고실적 프리미엄 |

- 여러 구간 동시 선택(OR). 각 버튼에 카드 수 표시.
- **불확실 지점**: "30만원대/40~50만원"을 더 잘게(30/40/50 각각) 나눌지, 혹은 3구간으로
  합칠지는 취향 문제. 현재는 위 5구간. 조정 원하면 `PRE_BUCKETS`(index.html) 수정.

### ④ 프리미엄 탭 — '혜택으로 찾기' + 필터 골드&블랙 테마
- `👑프리미엄` 탭 활성 시 `#section-cards.prem-theme` 아래에서
  `혜택으로 찾기` 박스와 3개 필터(버튼·팝오버·슬라이더·세그먼트)가 **골드&블랙**으로 전환.
- 골드 팔레트: 텍스트 `#e8c886`, 강조 `#c9a45c/#b8860b/#e3b448`, 골드 테두리 `#5c4a1f`.

### 관련 상태/함수 (index.html `<script>`)
- 상태: `selCompanies`(Set) · `feeIdx`([min,max]) · `selPre`(Set) · 상수 `FEE_STOPS/FEE_LABELS/PRE_BUCKETS`
- 함수: `toggleDd/closeAllDd`, `renderCompanyList/toggleCompany/setAllCompanies`,
  `onFeeSlide/updateFeeUI`, `renderPreSeg/togglePre`, 필터 반영은 `applyFilters()`.

## 3. 신용/체크 카드 분류 버그 수정 (`index.html`)

### 문제
`신용카드`·`체크카드` 탭이 **항상 0건**. LNB 버튼의 `data-cardtype`을 로드 시
`신용→CRD`, `체크→CHK`로 변환하는 코드가 남아 있었는데, 필터는
`c.card_type`(값이 `신용`/`체크`)와 비교 → `'CRD' !== '신용'` 로 전부 탈락.

### 수정
- 한글→코드 변환 블록(`{'신용':'CRD','체크':'CHK'}`) 제거.
- `data-cardtype`을 데이터의 `card_type` 값(`신용`/`체크`)과 **동일하게** 유지 → `applyFilters()`의
  `c.card_type !== activeCardType` 비교가 정상 동작.
- 데이터 자체는 정상이었음: `card_type` 신용 1,111 / 체크 452.

### 결과 (탭별 건수)
전체 1,563 · 신용 1,006 · 체크 452 · 프리미엄 105.
※ 신용 1,111 = 신용탭 1,006 + 프리미엄(연회비 15만↑ 신용카드) 105. 프리미엄은 별도 탭으로 빠지는 기존 설계.
