# 혜택 데이터 전수 검수 가이드 (3인)

카드 요율(할인율·적립률·정액원)과 전월실적 구간별 한도를 **원문과 대조해 확정**하는 작업.
기계 파싱(DB·JSON)은 근사치라, **원문이 정답**이다. 사람이 확인한 것만 계산기에 반영된다.

## 왜 하나
- DB의 구간 한도는 파싱이 깨진 게 많아(1·5원 등) 자동으로 못 쓴다 → 사람이 원문 보고 채운다.
- **검수완료(done) 표시한 카드만** `build`가 계산기(benefits_structured.json)에 반영한다. 미검수는 계산기에 절대 안 들어간다(안전).

## 분담 (카드사 균등, 522/522/521)

| 담당 | 장수 | 주요 카드사 |
|------|------|-------------|
| 담당1 | 522 | KB국민, NH농협, IBK기업, BC바로, BNK부산, 제주 … |
| 담당2 | 522 | 신한, 롯데, 삼성, 우체국, iM뱅크, 광주 … |
| 담당3 | 521 | 우리, 현대, 하나, MG새마을, 전북, 씨티 … |

전체 배분은 `data/review_shards/_assignment.json` 참고. (인원·이름 바꾸려면
`python scripts/db_export_shards.py --owners 이름1,이름2,이름3` 재실행)

## 검수 방법

1. 로컬 서버 실행: `python serve.py` → 브라우저 `http://localhost:5500/review.html`
2. 우측 상단에서 **내 담당** 선택 → 내 카드만 뜬다.
3. 카드를 클릭해 펼치면 **왼쪽 = DB 값(수정 가능), 오른쪽 = 원문**.
4. 원문과 대조:
   - **요율**: %는 숫자(10=10%), 정액은 원, 주유는 원/L.
   - **구간**: `전월실적원:한도원`, 여러 개는 `;`로. 예 `300000:26000; 500000:30000`.
   - 원문에 없거나 애매하면 **비워두고** 메모에 근거를 남긴다(추정 금지).
5. 맞게 고쳤으면 **[✓ 이 카드 검수완료]**. 애매하면 **[검수중]** + 메모.
6. 다 하면 우하단 **💾 검수결과 내보내기** → `담당N.json` 다운로드.
7. 받은 파일을 `data/review_shards/담당N.json` 에 **덮어쓰기**(또는 관리자에게 전달).

## 반영 (관리자 1인)

```bash
python scripts/db_import_shards.py --apply     # 샤드 → DB 반영
python scripts/build_from_db.py                # DB → benefits_structured.rebuilt.json 생성
#   회귀 확인 후 문제 없으면 rebuilt 를 benefits_structured.json 으로 교체(promote)
```
- `build`는 **검수완료(human) 구간만** 계산기에 넣는다. 회귀 테스트로 숫자 급변 확인 후 교체.

## 규칙

- **자기 담당 샤드만** 수정. 남의 카드사 건드리기 전 팀 공유.
- **원문이 최우선.** 파싱값이 그럴듯해도 원문과 다르면 원문대로.
- **추정으로 채우지 않는다.** 모르면 비우고 `검수중`+메모.
- 브랜치·PR은 기존 `CONTRIBUTING.md` 준용. 커밋 메시지: `data: <담당> 검수 N장`.
- 공통 파일(`benefits_structured.json`·DB·스크립트) 교체는 **관리자가 build 회귀 확인 후**.
